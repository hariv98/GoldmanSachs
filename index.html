02 · Featured Project

Loan Credit Risk Assessment System

MS Access · SQL · Relational Database Design · ISE 519 (A+)
What I Built

A full end-to-end relational database application for loan credit risk evaluation — from applicant data capture through automated risk scoring to a final approval/denial output. Built entirely in MS Access with complex SQL logic at the core.

Data Model

Designed a normalized relational schema across six interconnected entities: applicant profile, credit bureau data, credit balance history, previous loan applications, installment records, and risk scoring output. Each form in the application mapped directly to a table, with referential integrity enforced through foreign key relationships.

SQL Logic

The risk scoring engine combined four SQL subqueries into a weighted final score:

-- Final Risk Score: weighted combination of 4 subqueries SELECT a.SK_ID_CURR, (u.Utilization_Score * 0.30 + d.Delay_Risk_Score * 0.25 + e.Ext_Source_Score * 0.25 + b.Debt_Load_Score * 0.20) AS Total_Risk_Score FROM Applications a LEFT JOIN Utilization_qry u ON a.SK_ID_CURR = u.SK_ID_CURR LEFT JOIN Installment_Delay_Risk_qry d ON a.SK_ID_CURR = d.SK_ID_CURR LEFT JOIN External_Source_Avg_qry e ON a.SK_ID_CURR = e.SK_ID_CURR LEFT JOIN Debt_Load_qry b ON a.SK_ID_CURR = b.SK_ID_CURR

Each subquery used nested joins, unions, NZ() null-handling, and IIF() conditional logic to compute its component score from raw transactional data. The final scoring query combined all four into a weighted total, which drove the approval/denial output.

Application Layer

Built six data-entry and visualization forms: Main Navigation, Bureau Data, Credit Balance, Credit History, Previous Applications, Risk Analysis (with bar chart visualization of the four risk components), and Final Decision Summary. The full workflow — from applicant data entry to automated decision — required no manual calculation.

Why this matters for Foundation Engineering: This project demonstrates relational database design, complex multi-subquery SQL, and end-to-end application development in a financial services context. The same patterns — data modeling, query logic, decision automation — are the foundations of data engineering at scale.

Statistical Demand Forecasting & Capacity Optimization

Python · XGBoost · SHAP · GAMS · EM 538 (A+)
Forecasting Model

Developed a demand forecasting pipeline in Python comparing four algorithms — Linear Regression, Random Forest, SVR, and XGBoost — using GridSearchCV with 5-fold cross-validation for hyperparameter tuning and RMSE as the primary evaluation metric.

Feature Engineering & Interpretability

Performed feature engineering from raw operational data including lag features, rolling averages, and calendar indicators. Applied SHAP (SHapley Additive exPlanations) analysis to identify the top demand drivers and communicate model outputs to non-technical stakeholders — translating black-box predictions into explainable insights.

Capacity Optimization

Fed XGBoost forecast outputs into a multi-period mixed-integer optimization model built in GAMS. The model translated demand forecasts into production, inventory, and workforce decisions across multiple planning periods while minimizing labor and operating costs under capacity constraints.

Stack: Python (pandas, NumPy, scikit-learn, XGBoost, SHAP) · GAMS · GridSearchCV · 5-fold cross-validation · RMSE evaluation

System Design

Designed and built a demand-driven inventory management system from scratch using Excel VBA — replacing entirely manual processes with automated data pipelines, business logic, and an operational dashboard.

Core Logic

Replenishment engine based on sales velocity: reorder triggered when current stock fell below one week of prior month's average daily sales (monthly average ÷ 4). Suggested order quantity: two months of average demand. Implemented FEFO (First Expired, First Out) logic with dual expiry tracking per SKU to manage multiple inventory batches simultaneously.

Automation Pipeline

Daily POS CSV export → VBA macro → automated stock reconciliation → dashboard refresh. The entire pipeline ran on a single trigger with no manual steps. Dashboard outputs: inventory on hand, days of inventory, low-stock alerts, overstock flags, expiry warnings, top sellers, slow movers, and markdown recommendations.

What this demonstrates: End-to-end system design, automation pipeline architecture, business logic implementation, and delivering measurable impact — ~$15,600 in annual savings from a system built without enterprise tooling.
